# MyGo 桌面版限定范围安全审查

日期：2026-10-10。对象：`desktop-mygo/`、Rust `desktop-stdio` 入口、严格系统凭据构造函数与独立打包/发布工作流。采用 quick、source-first、部分覆盖流程：4 个边界侦察、2 个审查者、1 个独立最终覆盖复核。没有兼容的旧 coverage ledger。

## 结论与证据边界

本轮没有保留的已确认漏洞或满足证据要求的待验证漏洞线索；不能解释为“没有漏洞”或完整安全认证。最终 ledger 为 5 个已覆盖单元、8 个延后单元、2 个范围外单元；一个超出委派范围的发送边界部分审查保存在历史 attempt 中。结构化 findings 与 coverage 两个 validator 均通过。按 quick 流程完成单轮审查和一次最终独立覆盖复核，没有用追加审查掩盖剩余缺口。

外部完整审计记录由维护者保留于独立审计目录，不包含真实邮件、密码、环境转储或目标生成产物。仓库保留此人工整理摘要与 [开发/打包验证](verification.md)，测试通过不自动替代安全覆盖。

## 已检查的源码控制

- 邮件正文只进入原生只读文本控件；不渲染邮件 HTML、脚本、远程图片或邮件派生导航 URL。
- 私有匿名进程管道、JSON 编码、请求/响应 ID 关联、方法白名单、大小限制与固定脱敏错误；没有对外本地 HTTP 监听。
- 系统凭据后端使用专用服务名；严格构造路径不生成旧明文 overlay。数据目录准备拒绝 legacy `.secrets` 与不安全叶节点类型。
- 编写中的发送账号固定；UI 不把 RPC 成功等同于送达，不自动重试未知结果，不 flush 其他已排队发送。
- 构建作业只读权限；发布单独 main-only 手动授权，精确标签与源码 SHA 相等才可发布，拒绝覆盖既有 Release。依赖、构建工具和 actions 固定，最终包解压后自检。

## 延后与范围外

- 生成安装脚本、安装/升级/卸载与旧客户端共存、平台权限和默认目录 ACL 尚未真机验收。
- IPC 每个能力的完整授权映射、异常回复后继续调用、EOF、锁等待和退出/单实例全部生命周期需要后续专门审查。
- OS 钥匙库 ACL、锁定/不可用行为与签名身份之间的访问控制尚未完成独立平台验证。
- 跨重启的草稿/发送状态及耐久幂等性不由两个 UI fixture 测试证明；既有 FFI/send、SMTP 重试和提交次序在本次完整覆盖之外。
- 全路径内存、基数、取消及累积资源限制尚未完整映射；现有 IMAP/SMTP/MIME/store 和上游 toolkit 实现不是本次完整审计对象。
- 依赖许可证库存与真实交付包仍需产物检查；同一 Release 的 SHA-256 提供字节一致性，不提供独立发布者认证。

最终复核后，对 Windows UTF-8 元数据、macOS 打包前签名、每包 helper 数量及 DEB 解压自检的修正由主审查者做增量源码检查与构建回归；不据此把延后单元提升为完整覆盖。

## 验证与发布限制

禁外网容器仅使用 dummy 数据与显式环境白名单，源代码/工具/依赖只读、写入 scratch，限制 CPU、内存、PID、磁盘、单文件和墙钟。不访问宿主钥匙串或真实邮箱。RustSec 检查锁定依赖没有报告已知漏洞；Go govulncheck 不可用，未声称完成 Go advisory 扫描。

macOS 为 ad-hoc、未公证；Windows 未 Authenticode；Linux 无发行仓库签名。真实邮箱收发、GUI 真机、生产签名和长期升级恢复尚未验收，只发布独立桌面预览版。
